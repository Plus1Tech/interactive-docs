REUSABLE CLIENT SUPPORT GUIDE

Client AI & MSP Support

Use this guide before escalating common user, Microsoft 365, device, network, application, integration, and AI issues.

Safe support rule

Do not reset tenants, rotate credentials, change permissions, delete data, disable security controls, or modify production workflows unless the client-specific instructions explicitly authorize it.

Client: Not configured
Primary contact: Not configured
Escalation: Not configured
Support hours: Not configured

How to use this guide

1. Choose the closest symptom

The wording does not need to match the ticket exactly. Pick the topic that best describes what the user sees.

2. Expand the topic

Select Open to see what the symptom usually means, safe checks, evidence to collect, and the stop point.

3. Escalate with evidence

Stop when the guide says to stop. Send the next technician the error, scope, time, IDs, and checks already completed.

Important: This guide is the common baseline. The client’s approved runbook, technical documentation, security policy, and change process always take priority.

AIAI gives a wrong, incomplete, or inconsistent answer
Technician can doClient context may be required

What this usually means: The request is ambiguous, the source was missing or outdated, the wrong model or tool was used, or the answer was generated without enough context.

Safe first checks

  1. Ask the user for the exact prompt, expected result, and source they expected the AI to use.
  2. Confirm the correct workspace, project, agent, model, and connected source were selected.
  3. Retry with one clear objective, the relevant source attached or linked, and the required output format.
  4. Ask the AI to identify its sources, assumptions, and unsupported points.
  5. Test the same prompt once in a clean chat to separate conversation-history problems from a broader issue.

Evidence to capture

Prompt, output, expected result, model/tool, source used, date/time, workspace, and clean-chat result.

Stop and escalate

Escalate repeated incorrect answers from an approved source, cross-client data exposure, policy violations, missing required citations, or failures affecting a production workflow.

AIAI is slow, unavailable, rate-limited, or usage is exceeded
Technician can doAdmin access may be required

What this usually means: The vendor may be degraded, the account may have reached a plan or rate limit, the request may be too large, or the network/browser may be interfering.

Safe first checks

  1. Confirm whether one user or multiple users are affected.
  2. Check the approved vendor status page and client service-health dashboard.
  3. Retry one small text request in a private browser window.
  4. Confirm the user is signed into the correct account, workspace, and subscription.
  5. Check for plan, quota, rate-limit, token-limit, or usage messages in the admin console.
  6. Reduce attachments and prompt size, then retry once.

Evidence to capture

User, account/workspace, exact error, request size, model, time/timezone, status-page result, and small-test result.

Stop and escalate

Escalate billing or quota changes, repeated 429/5xx errors, organization-wide outages, or production workflow failures.

IdentityUser cannot sign in or keeps getting prompted
Technician can doEntra admin for logsNo security bypass

What this usually means: The wrong tenant, stale browser session, license, MFA method, Conditional Access rule, device state, or Microsoft service may be blocking authentication.

Safe first checks

  1. Confirm username, tenant, device time, and internet connection.
  2. Test the same sign-in in a private browser window.
  3. Check Microsoft 365 service health and verify the user’s license.
  4. Confirm an approved MFA method is available.
  5. With admin access, open Microsoft Entra admin center, then Identity > Monitoring & health > Sign-in logs. Find the failed event and record status, failure reason, Conditional Access result, application, correlation ID, and timestamp.

Evidence to capture

User, tenant, app, exact error, timestamp/timezone, correlation ID, sign-in status, device, browser, MFA result, and scope.

Stop and escalate

Do not reset MFA, exclude users from policies, alter Conditional Access, disable security defaults, or grant licenses without authorization.

M365Outlook, Teams, OneDrive, or SharePoint is not updating
Technician can doAdmin may be required

What this usually means: The desktop app may have a stale session, sync may be paused, a file may be blocked, storage may be full, or Microsoft 365 may be degraded.

Safe first checks

  1. Test the web version of the same service.
  2. Check Microsoft 365 service health.
  3. Confirm the application is signed into the correct account.
  4. For OneDrive, check the cloud icon, paused sync, storage, problem files, unsupported names/paths, and files still open in another app.
  5. Restart the affected application and test with one small item.

Evidence to capture

User, app/version, web result, desktop result, sync icon/status, file/path, exact error, time, service health, and scope.

Stop and escalate

Do not delete caches, rebuild profiles, unlink libraries, move large data sets, or resync production content unless the client runbook authorizes it.

DeviceWebsite or cloud application is blank, looping, or behaving differently
Technician can do

What this usually means: A browser extension, stale session, blocked cookies, unsupported browser, cached site data, proxy, or endpoint security control may be interfering.

Safe first checks

  1. Record the URL, browser, version, and exact symptom.
  2. Test in a private window and in another approved browser.
  3. Confirm the browser is updated and system date/time is correct.
  4. Disable only user-controlled extensions for one test when policy allows.
  5. Check whether another user or device has the same problem.
  6. Capture browser console/network errors only when the technician is trained to do so.

Evidence to capture

URL, browser/version, private-window result, second-browser result, extension result, screenshot, time, user, device, and scope.

Stop and escalate

Do not weaken endpoint security, bypass certificates, disable managed extensions, or clear saved data that may contain unsynced work.

DeviceComputer is slow, frozen, crashing, or running out of space
Technician can doRMM access may be required

What this usually means: Resource pressure, low disk space, a failing process, pending restart, update issue, hardware warning, malware alert, or profile problem may be involved.

Safe first checks

  1. Confirm whether the issue is constant or tied to one app or action.
  2. Check uptime, CPU, memory, disk free space, and top resource-consuming processes.
  3. Review RMM alerts, update state, backup state, endpoint security, and hardware warnings.
  4. Close the confirmed problem app safely and restart the device when the user approves and no work will be lost.
  5. Confirm whether performance improves after restart.

Evidence to capture

Device, user, uptime, disk space, CPU/memory, app/version, error, recent changes, RMM alerts, and restart result.

Stop and escalate

Escalate blue screens, SMART/disk warnings, encryption issues, malware indicators, overheating, failed backups, repeated crashes, or business-critical downtime.

NetworkInternet, VPN, Wi-Fi, or remote access is not working
Technician can doNetwork access may be requiredNo infrastructure reboot

What this usually means: The issue may affect one app, device, user, site, the ISP, DNS, VPN authentication, or a client network service.

Safe first checks

  1. Determine scope: one application, one device, one user, one site, or all sites.
  2. Check cable/Wi-Fi state, airplane mode, signal, and VPN status.
  3. Test one known public site and one known internal resource.
  4. Run approved IP, gateway, and DNS checks without exposing sensitive network details.
  5. Check RMM, firewall, ISP, VPN, and monitoring status.
  6. For remote access, confirm the target device is powered on, online, and permitted by policy.

Evidence to capture

Scope, site, device, connection type, VPN error, IP/gateway/DNS result, affected resources, first failure time, and monitoring alerts.

Stop and escalate

Do not reboot firewalls, switches, access points, servers, ISP equipment, or site VPNs without the approved procedure and change authority.

WorkflowAutomation, integration, or workflow stopped running
Technician can inspectPlatform access requiredNo production changes

What this usually means: The trigger may not have occurred, a connection may have expired, a field or path may have changed, a vendor may be degraded, or one production step may be failing.

Safe first checks

  1. Confirm the expected trigger occurred and the input reached the correct client system.
  2. Find the last successful run and first failed run.
  3. Open the failed step and record status code, sanitized error, retry count, and run ID.
  4. Confirm the named connection exists and is not marked expired. Never reveal the secret.
  5. Check for changed fields, folders, endpoints, file names, permissions, licenses, or vendor incidents.
  6. Retry one safe test item only when the workflow is documented as idempotent.

Evidence to capture

Workflow, environment, run ID, last success, first failure, trigger input, failed step, error, status code, recent changes, and retry result.

Stop and escalate

Do not replay batches, edit mappings, rotate secrets, alter production logic, modify webhooks, bypass approvals, or change production data without authorization.

EmailEmail is missing, delayed, rejected, or landing in spam
Technician can doExchange admin for trace

What this usually means: The message may be in Junk or quarantine, redirected by a rule, delayed, rejected by policy, blocked by authentication, or never accepted by Microsoft 365.

Safe first checks

  1. Collect sender, recipient, subject, sent time, timezone, and NDR when available.
  2. Check Inbox search, Junk, Deleted Items, quarantine, inbox rules, and approved forwarding.
  3. In Exchange admin center, open Mail flow > Message trace and search with the narrowest useful window.
  4. Record whether the message was delivered, rejected, deferred, filtered, redirected, or pending.
  5. Review the NDR enhanced status code and check mailbox quota and service health.

Evidence to capture

Sender, recipient, subject, timestamp, Message-ID, trace result, NDR code, quarantine/rule result, and scope.

Stop and escalate

Escalate suspected compromise, spoofing, phishing, unexpected forwarding, mass rejection, transport-rule changes, connectors, or SPF/DKIM/DMARC and DNS changes.

SecurityPossible phishing, compromise, malware, or data exposure
Immediate security escalationUse client incident plan

What this means: This is a potential security incident, not normal help-desk troubleshooting. Preserve evidence and follow the approved response process.

Do now

  1. Record the user, device, time, alert/message, and what the user clicked, opened, entered, downloaded, or sent.
  2. Preserve the original message, headers, alert, screenshot, ticket, and RMM event.
  3. Contact the approved security escalation path immediately.
  4. Isolate, disable, revoke, reset, or contain only when the runbook and your role authorize it.

Do not

Do not click links, open attachments, forward suspicious content broadly, delete evidence, run unapproved cleanup tools, or promise resolution.

Evidence to capture

Who, what, device, date/time/timezone, message or alert IDs, actions already taken, affected data/accounts, and current impact.

Client-specific exceptions

No client-specific exceptions have been documented. Confirm the client technical documentation before making elevated changes.
